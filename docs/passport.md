# Паспорт проекта

> Шаблон для заполнения на паре 5. Примеры в скобках — из эталона ShoeShop.
> Файл живёт в репозитории: `docs/passport.md`

## 1. Название проекта

 „KaMaz“» 

## 2. Проблема

У магазина обуви нет единой системы учёта: остатки ведутся вручную, клиент не видит актуальное наличие и цену, а сотрудники тратят время на уточнение информации по телефону. 

## 3. Пользователи

Гость — просматривает каталог без входа; клиент — смотрит товары под своей учётной записью; менеджер — ищет, фильтрует и сортирует товары, просматривает заказы; администратор — добавляет, редактирует и удаляет товары и заказы. 

## 4. Цель проекта

 Дать клиенту быстрый доступ к актуальному каталогу обуви, а сотрудникам — удобный инструмент для ведения товаров и заказов.

## 5. Метрики успеха



- Поиск нужного товара — не более 3 действий.
- Каталог обновляется сразу после изменения товара, без перезапуска.
-  Некорректные данные (пустые поля, отрицательная цена) в БД не попадают.

## 6. Границы (что НЕ делаем)


- Нет онлайн-оплаты.
- Нет мобильного приложения.
- Нет доставки — только выдача в магазине.

## 7. Риски

  Мало товаров для каталога - взять ассортимент из открытых источников.
 Ошибки при импорте - сначала проверять файлы вручную.
